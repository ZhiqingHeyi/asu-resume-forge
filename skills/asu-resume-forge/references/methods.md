# 核心方法论：阿酥六层技法 × 六问重构

## 一、阿酥简历的六层技法（ distilled from LofiSu 公开简历）

1. **定位层**：每一段都是「项目 Owner，完全负责从 0 到 1 设计并落地」。
   写的不是"干过什么"，而是"造出了什么"。Owner 视角把候选人从执行者拉到创造者位置。
2. **结构层**：固定三段式——背景与目标 → 指标与效果 → 我的职责。
   HR 5 秒扫"指标与效果"，技术面试官深读"我的职责"，两类读者各取所需。
3. **技术层**：职责里写完整链路（意图识别 → 条件路由 → 工具调用 → 失败回退……），
   每个项目都有"可追问"的技术纵深，而不是一句"搭建了 xx 平台"。
4. **量化层**：每段 3~5 个指标，业务指标与 Benchmark/技术指标双线并行，
   没有一句空泛的"提升了效率"。
5. **背书层**：硬背书（开源数据、可访问作品、GitHub）放在最显眼的位置，可验证、可追溯。
6. **视觉层**：模板干净；重点用加粗/颜色分层；一句话项目信息卡（时间 | 方向 | 范围）。

## 二、六问重构法

普通简历是任务流水账："负责开发、参与联调、修复问题、配合上线。"
锻造后的每段经历必须回答六个问题：

```
为什么做      → 业务/技术痛点，一两句说清
你负责哪一段  → 个人边界，角色强度分级（见下）
难点是什么    → 这件事真正难的地方（不是"时间紧任务重"）
如何设计      → 关键方案与取舍，链路级表达
结果如何      → 量化指标前置
怎么证明      → 可访问作品 / 数据口径 / 演示链接
```

## 三、角色强度四级（不得越级）

| 级别 | 用词 | 含义 | 追问时的证据 |
|---|---|---|---|
| L4 | 项目 Owner / 独立负责 / 从 0 到 1 | 需求定义到上线全程主导 | 能讲清每个决策的为什么 |
| L3 | 主导 / 核心负责 | 核心模块的方案与落地由你拍板 | 能画出模块架构图 |
| L2 | 负责 xx 模块 | 模块内独立交付 | 能讲模块级细节 |
| L1 | 参与 / 协助 | 在他人方案下执行 | 如实说做了什么 |

越级 = 造假候选。L1 的经历用 L2 的写法，面试 3 个问题就穿。

## 四、「难点 → 解法 → 收益」因果链

这是密度最高、也最容易缺失的一层。反例（最常见的失分项）：

```
× 负责智能客服工单系统的开发，使用大模型做意图分类，提升了客服效率。
```

锻造后：

```
√ 难点：工单文本口语化、长尾意图多，单模型分类置信度低，分派错误率高。
  解法：设计"规则 + 小模型 + 大模型三级路由"，低置信度自动升级，
  人工复核结果回流标注集形成评测闭环。
  收益：平均处理时长 4h → 30min，首次分派准确率 71% → 93%。
```

## 五、持续价值指标（容易被忽略的加分项）

除了一次性结果，阿酥会写"复购与主动推荐率持续增长"。对应写法：

- 定时任务持续运行 → "复购式使用"；
- 多部门常态化使用 N 个月 → "留存"；
- 平台 Top1 高频应用 → 相对排名；
- 上线至今零事故 / 数据不出内网 → 质量背书。

## 六、叙事顺序：指标前置

7.0 的"痛点 → 动作 → 成果"把数字埋在段尾；阿酥把"指标与效果"放在职责之前。
HR 平均 6~10 秒扫一份简历，数字必须在视线路径的前 1/3。
