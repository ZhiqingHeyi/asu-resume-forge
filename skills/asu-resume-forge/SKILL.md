# ASU FORGE · 阿酥式简历锻造炉

把"职责流水账"锻造成"作品级履历"。本 Skill 蒸馏自阿酥（LofiSu）公开简历的高密度叙事方法，并融合了
真实锻造场景（AI 产品经理 / Agent 全栈 / 中台架构师 / FDE 四类岗位）的经验沉淀。
本 Skill 内所有示例数据均为**虚构构造**，不对应任何真实个人。

**铁律：只放大，不虚构。** 每一条强表述都必须通过"15 分钟追问测试"——面试官就这句话连续追问 15 分钟，
候选人都能答得上来、拿得出证据。守不住的，降级或删除。

## 锻造流水线（F1 → F7，顺序执行，F5/F7 不过 = 不算成稿）

```
原始材料 → F1 事实账本 → F2 六问重构 → F3 岗位透镜 → F4 链路行铸造
        → F5 指标口径校验★ → F6 抓手埋点 → F7 红线门禁★ → 成稿交付
```

### F1 事实账本（Fact Ledger）
先把原材料里**只有事实、没有修辞**的信息全部登记：公司/学校/时间/角色/动作/数字/证据链接。
任何无法从原材料确认的信息，进「待确认清单」，**不得自行补全**。模板见 `references/fact-ledger.md`。

### F2 六问重构
把每段经历从"干了什么"重构成回答六个问题（详见 `references/methods.md`）：

```
为什么做 → 你负责哪一段 → 难点是什么 → 如何设计 → 结果如何 → 怎么证明
```

输出固定三段式（阿酥阅读动线，HR 5 秒扫指标、面试官深读职责）：

- **背景与目标**：为什么做，痛点是什么（一两句，别铺陈）；
- **指标与效果**：量化结果前置，业务指标 + 技术指标双线；
- **我的职责**：第一句定角色强度，然后写"难点 → 解法 → 收益"因果链。

### F3 岗位透镜（Job Lens）—— 本 Skill 独创
**同一份事实账本，绝不用同一套措辞海投。** 按目标岗位切换叙事透镜，规则见 `references/job-lenses.md`：

| 透镜 | 叙事重心 | 关键词 |
|---|---|---|
| 产品经理 | 洞察 → 决策 → 业务结果 | 痛点、评测驱动、转化率、成本 |
| 全栈工程师 | 实现链路 + 工程质量 | FastAPI、RAG、SSE、Function Calling |
| 架构师 | 权衡与取舍 | 架构链路、选型理由、边界与隔离 |
| FDE | 交付闭环 + 现场能力 | 私有化部署、排障、验收、推广路径 |

### F4 链路行铸造（Chain Line）—— 本 Skill 独创格式
每个核心项目铸造一条 `↳ 技术链路` 行：用箭头链写清实现路径，例如：

```
↳ 技术链路：工单文本清洗与脱敏 → Embedding 向量化 → 小模型意图分类
  → 置信度阈值判定 → 低置信度升级大模型 → 规则兜底 → 分派执行
  → 人工复核回流标注
```

链路行的双重作用：过筛时证明"真做过"；面试时主动递给面试官"追问的抓手"，
把面试节奏引到自己最熟的领域。**每环都必须能口头展开 3 分钟，讲不清的环节不上链。**

### F5 指标口径校验（Metric Audit）★ 不可跳过
对所有数字做重算与交叉验证，规则见 `references/metric-check.md`。最常抓的三类：

1. **重算**：时间压缩率 = (原时长 − 新时长) / 原时长。示例：4h→30min 是**缩短 87.5%**
   （对应速度提升 8 倍），原稿写"提效 8 倍"——"8 倍"根本不是一个存在的口径。
2. **自洽**：同一段落内的提效、成本、规模数字必须能互相推导。示例：耗时缩短到 1/8，
   成本却写"1/10"，低于理论下限——除非补上"大小模型分层路由"这个额外归因，否则就是硬伤。
3. **可归因**：个人指标与团队指标分离；"公司/平台/团队"的量不自动变成个人成果。

### F6 抓手埋点（Hook Planting）
主动在能力矩阵与项目段埋入"面试官可以追问、我正好能答"的技术词汇锚点
（如 Function Calling、混合检索、上下文工程、分层路由、回退机制）。
每个锚点必须满足：① 简历语境里真实用过；② 候选人能讲 3 分钟；③ 与岗位 JD 相关。
禁止堆砌自己讲不清的热词——埋的不是词，是面试的主动权。

### F7 红线门禁（Red-line Gate）★ 不可跳过
逐条过 `references/inflation-patterns.md`，核心红线：

- 不虚构经历、数字、头衔；角色词不得越级（参与 ≠ 负责 ≠ 主导 ≠ Owner）；
- "0→1"必须说明"0"指什么（新服务 / 新链路 / 新产品）；
- 极值词（最/首/唯一）必须有可验证的限定范围；
- 规划中的方向不得写成已上线收益（时态边界）；
- 作品列表与项目经历必须互相印证（实战踩坑：作品集里两个"作品"其实是同一平台的不同模块，
  会让面试官误判经历数量——必须在命名和备注里写清归属关系）；
- 所有链接、截图、演示地址必须真实可访问。

## 工作模式

- `Forge`（默认）：完整走 F1→F7，围绕目标岗位重建简历。
- `Polish`：保留原结构，只做措辞、顺序、密度与口径修复。
- `Audit`：不改写，只输出问题清单（口径矛盾 / 角色越级 / 缺指标 / 追问风险）。
- `Interviewer`：扮演面试官，对每句强表述做 15 分钟追问模拟，输出"守得住 / 守不住"判定。

## 交付

默认交付：① 问题诊断（原稿失分点）→ ② 锻造后简历（docx 或 markdown）→ ③ 修改说明
（每处改动对应哪条规则）→ ④ 追问备考清单（每个抓手锚点的 3 分钟口径）。
