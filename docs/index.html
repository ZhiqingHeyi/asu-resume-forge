01 / THE PAIN

简历最大的敌人，不是经历普通
是写成了「职责流水账」

甚至是一个算错的百分比——它会让面试官怀疑你简历上的所有数字。看这道工序抓出的硬伤（示例数据）：

BEFORE · 流水账 
• 负责智能客服工单系统的开发，使用大模型
  做意图分类，提升了客服效率。

• 工单平均处理时长从 4 小时缩短到 30 分钟
  （提效 8 倍），人力成本降低到原来的
  1/10。
病灶 —— 4h→30min 是耗时缩短 87.5%（速度提升 8 倍），"提效 8 倍"口径不存在；仅靠提速成本最低只能到 1/8，"1/10" 缺归因即矛盾；职责无边界、无难点、无链路。
VS
AFTER · 锻造后 
• 指标与效果：处理时长 4h→30min（缩短
  87.5%）；引入大小模型分层路由后成本降至
  1/10；首次分派准确率 71%→93%。
• 我的职责：项目 Owner，完全负责从 0 到 1：
  难点——工单口语化、长尾意图多，置信度低；
  解法——规则 + 小模型 + 大模型三级路由。
↳ 技术链路：文本清洗脱敏 → 向量化
  → 小模型意图分类 → 置信度判定 → 升级大模型
  → 规则兜底 → 分派执行 → 复核回流标注
锻后 —— 口径正确可重算、成本有独立归因；角色强度显性；难点→解法→收益成链；链路行给面试官递上"追问的抓手"。

03 / WHY US

三大独创，来自真实锻造实战

不是纸上谈兵的方法论——每一招都能在「同一份事实 → 四份岗位简历」的锻造里验证。

独创 · 壹

岗位透镜

事实账本只有一本，叙事透镜各配一副。同一段经历，PM 版讲业务结果，全栈版讲实现链路，架构版讲取舍，FDE 版讲交付闭环——数字完全一致，叙事各不相同。

架构取舍：复用开源 RAG 框架而非自研
向量检索引擎，换取 1.5 个月上线窗口
独创 · 贰

链路行 Chain Line

每个核心项目一条 ↳ 箭头链，把"搭建了 xx 平台"还原成组件级数据流。过筛时证明真做过，面试时把追问引向你最熟的领域。

↳ 意图识别 → Function Calling 工具调用
→ RAG 混合检索 → SSE 流式输出
独创 · 叁

指标口径校验

重算、自洽、可归因三关。抓出「提效 8 倍 + 成本 1/10」这类双硬伤（口径不存在，且成本低于理论下限）——一个错数，毁掉所有数字的可信度。

压缩率 = (原时长 − 新时长) / 原时长
每个派生数字都要能当场算清
04 / JOB LENSES

四副岗位透镜，拒绝一份简历海投

产品透镜

叙事重心：洞察 → 决策 → 业务结果。技术是手段，业务变化是主角。
段首"背景与痛点：……" 从业务问题开场
指标效率提升 · 成本下降 · 转化率 · 释放工时
职责需求定义 · 交互创新 · 评测驱动迭代
链路↳ 产品链路（技术词以产品机制串联）

全栈透镜

叙事重心：实现链路 + 工程质量。每个项目都要能还原出数据流向。
段首"背景与目标：……" 从技术问题开场
矩阵Function Calling · MCP · 上下文工程 · RAG · SSE
指标准确率 · 延迟 · 调用量 · 数据集规模
链路↳ 技术链路，写到组件级（谁调用谁）

架构透镜

叙事重心：权衡与取舍。架构师的简历里必须有"为什么这样选"。
句式"架构取舍：牺牲 A，换取 B"
指标系统规模 · 复用率 · 隔离边界 · 可观测
职责分层设计 · 选型理由 · 演进路径
链路↳ 架构链路：注册中心 → 编排 → 回退 → 隔离

FDE 透镜

叙事重心：交付闭环 + 现场能力。价值在落地之后还在增长。
栈Docker-Compose · Nginx 反代 · 鉴权打通 · 日志排障
指标覆盖部门数 · 零事故 · 验收通过率 · 复购式使用
职责需求转化 · 私有化交付 · 培训推广 · 复盘迭代
链路↳ 交付链路：调研→勘察→部署→打通→培训→复盘
