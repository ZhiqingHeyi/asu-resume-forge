# 锻造示例：同一段经历，5 道工序的 5 次改写

> **本案例为教学用的构造示例**：人物、公司、项目与所有数字均为虚构，
> 不对应任何真实个人、团队或产品。
> 之所以虚构，是因为任何"真实脱敏案例"都可能被反向识别出当事人——
> 而 ASU FORGE 的第一条红线就是**不泄露候选人信息**。
> 案例结构与方法调用是真实的，可直接照搬到你的经历上。

设定：一位 AI 应用工程师，核心经历是「智能客服工单分派系统」与「企业知识库问答平台」。

---

## 案例 1：指标口径硬伤（F5 抓出）

**Before**

```
工单平均处理时长从 4 小时缩短到 30 分钟（提效 8 倍），
人力成本降低到原来的 1/10。
```

**两处硬伤：**

1. **口径错**：4h→30min 是**耗时缩短 87.5%**，对应**处理速度提升 8 倍**。
   "提效 8 倍"是个不存在的口径——既不是 87.5%，也不是 800%。
2. **自相矛盾**：单纯提速最多把人时成本压到 **1/8**（因为工时正好缩短到 1/8），
   而"1/10"比理论下限还低。缺了归因，就是个经不起追问的数字。

**After**

```
工单平均处理时长 4h→30min（耗时缩短 87.5%，处理速度提升 8 倍）；
引入大小模型分层路由后，单工单推理成本降至原方案的 1/10。
```

补上"分层路由"这个归因，"1/10"就从矛盾变成了可解释。**修复不是改数字，是补因果。**

## 案例 2：职责流水账 → 难点因果链 + 链路行（F2 / F4）

**Before**

```
• 负责智能客服工单系统的开发，使用大模型做意图分类，提升了客服效率。
```

**After**

```
• 背景与痛点：客服工单日均 3000+，人工分派平均等待 4 小时，
  30% 工单因分派错误需要二次流转，重复占用坐席产能。
• 指标与效果：平均处理时长 4h→30min（缩短 87.5%）；首次分派准确率
  71%→93%；二次流转率 30%→7%；人工坐席由 10 人减至 4 人。
• 我的职责：项目 Owner，完全负责从 0 到 1 设计并落地：
  难点——工单文本口语化、长尾意图多，单模型分类置信度低；
  解法——规则 + 小模型 + 大模型三级路由，低置信度自动升级，
  人工复核结果回流标注集，形成评测闭环。
↳ 技术链路：工单文本清洗与脱敏 → Embedding 向量化 → 小模型意图分类
  → 置信度阈值判定 → 低置信度升级大模型 → 规则兜底 → 分派执行
  → 人工复核回流标注
```

**改了什么**：职责从"做了什么"变成"为什么难、怎么解、结果如何"；
链路行把"用了大模型"还原成 8 个可追问的环节。

## 案例 3：作品 - 项目一致性（F7 第 13 条）

**Before**：作品集平铺「DocuMind 文档问答」与「企业知识库平台」——
看似两个独立作品，实则前者只是后者的一个应用模块。面试官会据此误判经历数量，
追问时一戳就破。

**After**

```
在线作品：
  企业知识库平台 · 文档问答 DocuMind（平台的问答应用模块，非独立产品）
  工单智能分派系统（独立搭建，不依赖知识库平台）
```

**原则**：宁可少写一个"作品"，也不要让两个名字指向同一次经历。

---

## 案例 4：岗位透镜切换（F3）

同一段「企业知识库平台」经历，四份简历的段首与重心各不相同：

- **PM 版**：「背景与痛点：员工找一份制度文件平均要 20 分钟……」
  → 讲**业务结果**（检索准确率 93%、人均每天节省 20 分钟）
- **全栈版**：「背景与目标：缺少统一的检索与问答底座……」
  → 讲**实现**（FastAPI / Celery / pgvector / SSE 流式输出）
- **架构版**：补**架构取舍**——"复用开源 RAG 框架而非自研向量检索引擎，
  换取 1.5 个月上线窗口"
- **FDE 版**：讲**交付链路**——"调研 → 环境勘察 → 容器化部署 → SSO 鉴权打通
  → 培训 → 复盘" + 零安全事故

**四份简历数字完全一致，叙事各不相同。** 事实账本只有一本，透镜各配一副。

## 案例 5：抓手埋点（F6）

**Before**：能力矩阵只有"熟悉大模型应用开发，了解 RAG"。

**After**：注入可追问锚点——

```
AI 应用核心技术栈：大模型 API 接入与大小模型分层路由（推理成本降至 1/10）、
Function Calling 与工具调用链路、MCP 等工具接入协议、Agentic Workflow 编排、
上下文工程（写入 / 选择 / 压缩 / 隔离）、向量检索与 Rerank 重排。
```

**埋点三原则**：① 简历语境里真实用过；② 自己能讲 3 分钟；③ 与目标岗位 JD 相关。
三条缺一不可——**埋的不是词，是面试的主动权；埋错就是给自己挖坑。**
